Equipment planning and execution (MoP Classic, Interface 50504)

EquipmentInventory scans carried bags 0..NUM_BAG_SLOTS and enriches equipped
observations. Candidates retain bag/slot, item ID, link fingerprint, GUID when
available, stack count, locks, equip location, and decoded modifications.
Only free general-purpose bag slots receive explicit displaced-item moves.
Banks are outside the scan.

EquipmentPlanner reserves matching physical instances, including resolved
ring/trinket assignments. Other targets require exact item IDs; known modification
matches help choose among duplicates. Matching equipment is not replaced solely
to improve modifications. One physical instance cannot fill two targets.
Ambiguous duplicates without sufficient identity evidence stay blocked.

The global Equip hardware click submits the available plan synchronously.
Selected-slot clicks use the same planner/executor with a restricted target;
weapon selection includes the pair to preserve transition dependencies.
Ordinary slots precede ordered weapon work. Two-handed transitions and explicit
off-hand removal retain bag-space and class restriction checks.

Unique full-link fingerprints use C_Item.EquipItemByName with a destination slot.
Identical fingerprints requiring instance selection use exact container/inventory
pickup, native slot acceptance, inventory placement, and displaced-item return.
Both paths recheck source identity, GUID/location, locks, and cursor state.
A pre-existing cursor item is never cleared. Combat and unavailable source data
block submission. Native restrictions still apply.

Submission is not completion. Equipment/bag/lock events trigger observations that
verify each destination by GUID, or conservative fingerprint/source-movement
evidence when GUID is unavailable. The four-second final rescan resolves pending
records without equipping. Pending work blocks another batch; terminal failures
can be retried by a new click. An unexpected cursor item blocks further submissions.

Equipment Manager synchronization uses EquipmentSetSync after verification.
Selected-slot work does not save a partial outfit. See managed-builds-notes.txt
for exact-name destination and option behavior.
