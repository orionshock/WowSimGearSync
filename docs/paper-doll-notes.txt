INV_Chest_Plate04 texture. Left-click toggles PaperDoll; right-click toggles the
existing import window. Tooltip shows active/latest build and mouse actions.

or persistence has been introduced. Slash registration/dispatch is unchanged.

PAPER DOLL
PaperDoll.lua owns frame lifecycle and presentation, kept together as one
cohesive UI module under the repository's 300-line review threshold. No scanner
or comparator logic is copied. Opening calls the existing scanner and comparator
once; Render binds their exact targets, snapshot slots, differences and assignment
objects. Empty/latest builds share the same 16 reusable buttons. Import sends an
AceEvent message after saving; visible paper dolls refresh immediately.
Two equipment columns and bottom main/off-hand slots use the authoritative
EquipmentSlots tokens with GetInventorySlotInfo for empty-slot textures.
The existing portrait, close, and panel-button templates supply the frame shell.
Escape closes it; background dragging moves it. Import shows the existing editor.
Equip stays disabled and explicitly says automation is not implemented.
Plain slot buttons have no click, drag, item-use or secure equipment handlers.

Target item icons/names/quality come from C_Item.GetItemInfo/GetItemInfoInstant.
Unknown names fall back to item IDs; unknown icons to the question mark. Quality
borders remain intact, with a separate differential badge:
= green: correct item, all requested/eligible modifications confirmed.
~ amber: known configuration mismatch; ~? also has unknown fields.
! red: target item is missing or wrong.
? blue: required observations remain unknown.
- gray: empty target (tooltip still shows any item mismatch).
Tooltips show target/current links or IDs, every comparator field, numeric values,
remaining upgrades, unknown reasons, and per-socket results. Resolved ring and
trinket physical slots are taken directly from currentPosition/currentSlotId;
assignment labels distinguish inferred pairing from observed inventory data.
