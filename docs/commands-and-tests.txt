Native AceConfigCmd commands and in-game tests (Task 011)

REGISTRATION AND ROOT BEHAVIOR
Commands.lua registers the existing options table with AceConfig under
"WowSimGearSync" and calls AceConfigCmd:CreateChatCommand("wsgs",
"WowSimGearSync"). AceConfigCmd solely owns registration, dispatch, argument
handling, and help output; it uses AceConsole internally. Root /wsgs displays
standard AceConfigCmd help. There is no custom dispatcher, input normalization,
root window toggle, completion candidate generator, or manual chat hook.
Debug and Engineering recommendations use native toggles; compare/import execute
options; probe/test validated inputs. /wsgs engineering controls recommended tinkers.
/wsgs import creates the existing import window if needed and toggles it; repeated
invocations open/close it. Escape closes it, including while the JSON editor is focused.
Root /wsgs still shows native help.
Core.lua retains AceAddon initialization and AceDB defaults. Settings remain
in db.profile, simulation builds/sequence/latest tracking in db.char.
SavedVariables remains commented out. The LDB launcher now opens the paper doll
on left-click and toggles import on right-click; see paper-doll-notes.txt.

LIBRARIES AND COMPLETION LIMITATION
Unmodified library source: C:\WoWAddons\Ace3, Release-r1403.
Load order: LibStub -> CallbackHandler -> AceAddon -> AceEvent -> AceConsole
-> AceDB -> AceConfigRegistry -> AceConfigCmd -> AceConfig -> AceTab.
AceConfig's aggregate XML includes Dialog/AceGUI; these are unnecessary for
command-only use, so the required Lua files are loaded directly instead.
The source BSD license remains in Libs/Ace3-LICENSE.txt; library headers remain.

The bundled AceConfigCmd-3.0 minor 14 CreateChatCommand() comment advertises
AceTab integration, but its implementation only registers through AceConsole
and records commands[slashcmd]=appName. GetChatCommandOptions() exposes that
association. No call to AceTab/RegisterTabCompletion is made, and the bundled
AceTab-3.0 minor 10 never consumes AceConfigCmd's command/options registry.
Thus CreateChatCommand does NOT register a completion tree with this AceTab.
AceTab remains bundled and loaded but no WSGS-specific completion set is
registered. Physical Tab completion is unverified and is not claimed to work.
No workaround, library patch, or manual hooks have been added.

MALFORMED JSON REGRESSION
Confirmed runtime evidence: DeserializeJSON("{broken") can return a table.
Blizzard EncodingUtilDocumentation.lua declares a nullable LuaValueVariant,
not a guarantee of exceptions or non-table results for malformed text.
The corrected case decodes using the real API and, if decoding returns normally,
passes the result to production ValidateEquipment(). It requires rejection with
an error reason. A decoder exception is also rejection, as in the real importer.
It checks that collection identity, existing build references and the selected
build ID remain unchanged. It never calls the saving ImportEquipment() method
or substitutes a test database. No native decoder replacement is used.

IMPORT WINDOW PRESENTATION (TASK 014)
The PortraitFrameTemplate import dialog contains the JSON editor, Import and
error display. FULLSCREEN_DIALOG keeps it above the DIALOG paper doll; showing
it or clicking its background/editor/controls raises it. Success validates and
updates a specialization-managed build, selects it, refreshes the visible doll
and closes import. Failure preserves existing builds and pasted JSON, keeping
the editor open. Reopening clears errors. There is no import name or ID listing.
Rename the selected build in the doll's top field; Enter saves, Escape or focus
loss cancels. Empty/overlong names are rejected. Names survive reimport.
Detailed storage, Engineering evidence and runtime checks: managed-builds-notes.txt.

TASK 016 IMPORT POLISH / ESCAPE
Title: Import Equipment from WoWSims JSON. Instruction: Paste at least the Gear
from WoW Sims JSON Export. Interior heading, version and footer hint removed.
Import is anchored BOTTOMRIGHT (-24,+22). The editor and error region use frame
anchors, reserving space above the action row; JSON validation is unchanged.

Blizzard UIParentPanelManager/Shared/UIParentPanelManager.lua:1041 iterates all
UISpecialFrames entries, resolves _G[name] and hides each visible frame. It does
not stop at the top window. Both old per-window registrations are removed.
A single WSGSEscapeWindow alias points to visible import (FULLSCREEN_DIALOG),
otherwise the visible doll (DIALOG), otherwise nil. OnShow/OnHide update it.
Blizzard captures each entry's frame before hiding; retargeting the alias during
OnHide cannot close the underlying doll in that same iteration. No global hook,
replacement Escape binding or keyboard listener is installed. Focused JSON uses
its existing OnEscapePressed handler and normal native EditBox key consumption.

Runtime UI cases check native Escape registration and two-step closing,
focused editor after failure, and each window alone. Layout/copy checks were
removed under the repository testing policy. They drive the exact alias Hide path or EditBox handler, not physical keys.
They never call CloseSpecialWindows globally, so unrelated user UIs stay open.
Existing success/failure lifecycle tests remain. Counts after test cleanup: UI 13, all suites 50.
These are registered cases, not asserted in-game passes.
