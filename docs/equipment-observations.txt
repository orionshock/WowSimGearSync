Equipment observations and comparisons (MoP Classic, Interface 50504)

Equipment State owns captures, invalidation, shared item-data requests, and
read-only results. Captures include equipped observations, carried candidates,
modification-material indexes, character context, normalized target slots,
physical assignments, and comparison summaries. The two bag traversals remain
separate: EquipmentInventory retains instances and general bag destinations;
ModificationMaterials derives preferred material/use-spell lookups. Execution
always revalidates live data.

GetInventoryItemID plus GetInventoryItemLink establishes equipped identity.
Nil ID and nil link establish an empty slot; errors/inconsistent reads stay
UNKNOWN. C_Item.GetItemGUID supplies instance identity when available.
ItemLinkDecoder preserves empty fields and accepts raw/colored item links.
Verified fields after the item prefix:
1 item ID; 2 ordinary enchant; 3-6 gems; 9 player level; 10 reforge.
No link field supplies upgrade progress or tinkers. Field 11 is not interpreted
as specialization. Explicit zero/empty values differ from unreadable data.
EquipmentInspector supplies upgrades and profession-effect observations; see
upgrade-and-tinker-notes.txt.

The scanner captures professions once in context.professions. Action preparation
reuses this table; profession execution rescans the live profession/spellbook.
SKILL_LINES_CHANGED and SPELLS_CHANGED invalidate observations for a new capture.

The comparator returns profileName, slots, assignments, and summary. Rings and
trinkets evaluate direct/swapped pairings, prioritizing item identity and then
known modification differences. Exact ties keep direct mapping. An assignment
cannot reuse a physical slot. Different item IDs never match.
Only imported gem positions are compared. Omitted enchant/reforge targets are
not removal requests. Explicit tinkers win over the optional cloak fallback.
Wrong or unknown items cannot receive modification MATCH claims.

Upgrade policy is MAXIMUM independently of imported upgradeStep. Configuration
mismatches count fields, not actions; unknown required gem sockets can contribute
separately. Hiding icons on wrong items does not change totals. Buckle and
profession socket requirements remain independent prerequisites.

Equipment State caches the current build capture and invalidates on relevant
equipment, bag, lock, profession/spellbook, and import events. Item-data requests
share subscribers, with ITEM_DATA_LOAD_RESULT as authoritative request completion.
UI refreshes are deferred/coalesced, not polled.
/wsgs compare prints the active comparison; /wsgs probe 1..16 inspects export
positions, not inventory slot IDs. /wsgs debug controls verbose logging.
