STRUCTURES AND RULES
Snapshot: {capturedAt, slots[1..16]}; each slot includes position, slotId,
slotName, id/link when available, observations[field]={status,value,source,
reason}. Item includes present=false for known empty; empty-slot modifications
are NOT_APPLICABLE. Gems contain four values[index] observation records.
Decoder also reports playerLevel; this is not specialization metadata.

Comparison: {profileId,profileName,slots,assignments,summary}. Each slot has
physical/target positions and inventory IDs, per-field states and expected/
actual values, evidence source/reasons, and per-socket gem details. Only
explicitly specified gem positions are compared. Omitted enchant/reforge/
tinker properties are NOT_APPLICABLE and never removal instructions.
Unknown or wrong items cannot receive modification MATCH claims.
Unmapped mixed scalar representations remain UNKNOWN.

Rings (11,12) and trinkets (13,14): evaluate direct/swapped assignments by item
mismatches; when both assignments match both IDs, known modification differences
break ties. Exact ties keep direct mapping. Assignments never reuse a slot.
Summary counts item matches including intended empties; configuration mismatches
count fields, not actions. Unknown counts required scalar/item fields and
individual compared gem sockets; blocked gem fields count once. Maximum-upgrade
uncertainty contributes UNKNOWN even if upgradeStep is omitted from the export.
