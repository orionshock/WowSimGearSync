STRUCTURES AND COUNTING
Snapshot: {capturedAt, slots[1..16]}. Each slot has position, slotId, slotName,
id/link when available, and observations[field]={status,value,source,reason}.
Item observations include present=false for a known empty slot. Gem
observations contain values[index] with independent status/value records.
Empty slots have NOT_APPLICABLE modifications; unreadable data has UNKNOWN.

Comparison: {profileId,profileName,slots,assignments,summary}.
Each slot records target/current positions and inventory IDs, and fields
item/gems/enchant/reforging/upgradeStep/tinker with state, expected, actual,
source/reason where applicable. Gem results retain per-socket differences.
Unknown item identity or wrong item prevents modification MATCH claims.
Omitted properties are NOT_APPLICABLE, never removal instructions.
Unmapped mixed scalar representations are UNKNOWN, not mismatches.

For rings (11,12) and trinkets (13,14), score direct and swapped assignments
by item mismatches. If both assignments match both IDs, known modification
mismatches break the tie. Exact ties retain direct assignment. Assignments
are bijective, so duplicate IDs cannot consume the same physical slot twice.
Summary matched counts item matches (including intended empty slots).
Configuration mismatches count fields per slot, not operations; gems count
as one mismatch field. Unknown counts required scalar/item observations and
individual gem sockets when socket comparisons are available, including
unknowns alongside known gem mismatches. A blocked gem field counts once. These numbers are diagnostics, not an automation queue.
